# ADR-0072: 문서 구조와 언어 정책 (한국어 본문 + 영어 요약, 추가 의존성 없음)

- 상태(Status): 채택
- 날짜(Date): 2026-09-16
- 관련 ID: R-14, 플랜 §4.2(`docs/`), §7 Phase 8, §12.1, 규칙 11.6
- 검증 출처(Sources):
  - `mkdocs.yml`(Phase 0 스캐폴딩): `theme.name: material`, `language: ko`, nav 에 `index.md`,
    `concepts/index.md`, `tutorials/{hyp3-quickstart,isce2-local,validate-tune}.md`, `kb/index.md`,
    `research/index.md`, `adr/…`, `open-questions.md`, `plan/…`
  - `pyproject.toml [project.optional-dependencies] docs = ["mkdocs>=1.6", "mkdocs-material>=9.5"]`
  - `docs/kb/index.md` 헤더: "generated by scripts/render_kb_docs.py from src/wintersar/diagnose/kb/*.yaml"
  - `src/wintersar/i18n/__init__.py`(모듈별 `i18n/{ko,en}/<module>.yaml` 병합), `qgis_plugin/build_zip.py`

## 맥락 (Context)

Phase 8 은 튜토리얼 3종(ko/en)·KB 정리·ADR 을 요구하고, 플랜 §12.1 은 온보딩용 개념 문서 초안을 준다.
연구자(주 독자)는 한국어를 쓰지만 코드·CLI·엔진 문서는 영어이므로 두 언어를 모두 다뤄야 한다.
mkdocs-material 의 다국어 플러그인(`mkdocs-static-i18n` 등)을 넣으면 의존성·빌드 복잡도가 늘고 전역
의존성 정책의 검증 부담이 생긴다.

## 선택지 (Options)

1. `docs/ko/`, `docs/en/` 이중 트리 + i18n 플러그인 — 모든 페이지를 두 번 유지해야 하고 플러그인 의존성 추가.
2. **한국어 본문 + 각 페이지 끝의 "English summary" 절** — 단일 트리, 의존성 없음, 영어 독자는 요약과
   코드 블록(명령·설정은 언어 중립)으로 따라갈 수 있다.
3. 영어 본문 + 한국어 요약 — 주 독자와 맞지 않음.

## 결정 (Decision)

선택지 2.

- **구조**(`docs/`): `index.md`(무엇/왜, 설치, 5분 합성 실행) · `concepts/`(§12.1 개념당 1페이지, `index.md`
  가 순서·연결) · `tutorials/`(HyP3 빠른 시작, ISCE2 로컬, 검증·튠) · `kb/`(생성물, 수정 금지) ·
  `research/` · `adr/`(`README.md` 가 번호 대역 색인) · `contributing.md` · `open-questions.md`.
  각 개념 페이지는 관련 규칙/ID(`SEL-xx`, `KB-xx`, `PERF-xx`)와 config 키를 명시해 코드와 왕복할 수 있게 한다.
- **언어**: 본문 한국어, 페이지 끝 `## English summary` 절(3~8문장 + 핵심 명령). 용어는 처음 나올 때
  "한국어(영어)" 로 병기하고 이후 영어 원어를 그대로 쓴다(relative orbit, burst, looks, layover 등 —
  연구자가 도구 로그·논문에서 만나는 단어이므로 번역하지 않는다).
- **수치 금지**: 문서에는 `bench_result.json` 이 없는 성능 수치·시간 예상을 쓰지 않는다(규칙 11.8).
  플랜의 "기대 효과"는 가설로만 언급한다.
- **명령은 트리에서**: 튜토리얼의 명령줄은 `src/wintersar/cli.py` 와 각 모듈 `cli.py` 에 실제로 있는
  옵션만 쓴다. 이 ADR 작성 시점에 없던 `validate`·`refpoint`·`sweep`·`bench`·`research` 는 모두
  구현됐다(2026-09-17 `COLUMNS=200 .venv/bin/wintersar --help` 확인 — `closure` 도 함께 있다).
  앞으로 트리에 없는 명령을 문서에 쓸 때만 "플랜 §4.5, 구현 예정" 으로 표시한다.
- **사용자 문구의 단일 원본**은 계속 `src/wintersar/i18n/{ko,en}{,/<module>}.yaml` 이다. 문서는 문구를
  복사하지 않고 ID(`SEL-01`, `KB-SNAPHU-001`)로 참조한다. QGIS 플러그인 문구는 `i18n/{ko,en}/qgis.yaml` 에
  두고 `build_zip.py` 가 JSON 으로 평탄화해 동봉한다(ADR-0070).
- **ADR 번호 대역**(`docs/adr/README.md`): 0001 공통, 0010–0019 select, 0020–0029 engines, 0030–0034 pipeline,
  0035–0039 diagnose, 0040–0044 validate, 0045–0049 unwrap, 0050–0054 io/compute/bench, 0060–0064 research,
  0070–0072 docs/qgis.

## 결과 (Consequences)

- 영어 독자에게는 요약만 제공되므로 v0.1 릴리스 노트에 이를 명시한다. 완전한 영어판이 필요해지면
  `mkdocs-static-i18n` 도입 여부를 별도 ADR 로 결정한다(의존성 정책 검증 포함).
- `mkdocs.yml` 은 공유 파일이라 이 ADR 에서 수정하지 않는다. nav 가 가리키는
  `plan/wintersar_implementation_plan.md` 와 `research/index.md` 는 2026-09-17 기준 `docs/` 아래에
  실재하므로 복사·심볼릭 링크 작업이 필요 없다(open-questions #65 완료).
- 개념 페이지 `concepts/geometry.md` 는 select/geometry 담당이 소유하며 `concepts/index.md` 에서 링크만 한다.
