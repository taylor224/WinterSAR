# 진단 지식 베이스(KB) 개요

> 이 파일은 저장소를 GitHub 에서 볼 때의 안내문입니다. mkdocs 사이트에서는 같은 디렉터리에 `index.md` 가 있으면
> `README.md` 를 무시하므로(MkDocs 사용자 안내 "Index pages"), 사이트의 KB 페이지는 생성물인
> [index.md](index.md) 입니다. 항목 목록·요약은 그쪽이 원본이며 여기에는 복사하지 않습니다.

## KB 가 하는 일 (R-02, R-14, PERF-13)

`wintersar diagnose <경로>` 는 엔진 로그를 KB 항목의 정규식과 대조해 **원인 → 조치 → 참고** 순서로 설명합니다.
`wintersar run` 은 단계가 실패하면 그 노드의 로그 디렉터리(`work/<stage>/<hash>/logs`, ADR-0032)에 같은 진단을
자동으로 붙입니다(ADR-0033). 매칭되는 패턴이 없으면 `KB-UNKNOWN` 과 마스킹된 로그 발췌를 남깁니다 — "모른다" 를
숨기지 않는 것이 Phase 3 DoD 의 일부입니다.

```bash
wintersar diagnose work/                       # 작업 디렉터리 전체 (엔진 자동 감지)
wintersar diagnose work/unwrap/<hash>/logs --engine snaphu
wintersar diagnose --list-kb                   # ID · 엔진 · 단계 · 심각도 · 검증 · retry 힌트 표
wintersar diagnose work/ --assume-failed       # 종료 코드가 없어도 실패로 간주하고 패턴 탐색
```

## ID 체계

`KB-<ENGINE>-<NNN>`. `<ENGINE>` 은 `ASF`, `AUTH`, `ENV`(공통), `HYP3`, `ISCE2`, `MINTPY`, `SNAPHU`. 번호는 엔진별로
1부터 증가하며 재사용하지 않습니다. 사용자 문구의 키는 `diagnose.<ID>.cause` / `diagnose.<ID>.fix`
(`src/wintersar/i18n/{ko,en}/diagnose.yaml`, 규칙 11.6) 이고 문서와 i18n 은 모두 KB YAML 에서 생성됩니다.

## 원본과 생성물

| 무엇 | 어디 | 수정 방법 |
|---|---|---|
| KB 원본 | `src/wintersar/diagnose/kb/*.yaml` (엔진별 파일) | 직접 편집 |
| 스키마 | `wintersar.diagnose.kb_loader.KBEntry` | 코드 |
| 문서 | `docs/kb/index.md`, `docs/kb/KB-*.md` | **편집 금지** — `scripts/render_kb_docs.py` 로 재생성 |
| 사용자 문구 | `i18n/{ko,en}/diagnose.yaml` 의 `diagnose.<ID>.*` | `scripts/render_kb_docs.py --write-i18n` |
| 로그 픽스처 | `tests/fixtures/logs/<engine>/*.log` + `manifest.yaml`(기대 ID·추출값) | 항목마다 최소 1개 |

```bash
.venv/bin/python scripts/render_kb_docs.py               # docs/kb/ 재생성
.venv/bin/python scripts/render_kb_docs.py --write-i18n  # + i18n 동기화
.venv/bin/python scripts/render_kb_docs.py --check       # CI: 생성물이 오래됐으면 exit 1
```

## 항목 스키마 (`KBEntry`)

| 필드 | 뜻 |
|---|---|
| `id`, `engine`, `stage` | ID, 엔진(`any` = 공통), 주로 나타나는 단계(없으면 `-`) |
| `pattern`, `ignore_case`, `extract` | 로그에 대한 정규식(컴파일 검증), 대소문자 무시 여부, 문구에 넣을 named group 이름 |
| `cause`, `fix` | ko/en 두 언어의 원인·조치 문구(`{param}` 치환) |
| `refs` | 참고 URL·문서 경로 |
| `severity` | `FAIL` / `WARN` / `INFO` |
| `retry_hint` | 파이프라인이 자동으로 취할 수 있는 조치: `retry_later`(네트워크·서비스), `tile`(메모리 → 타일 증가), `manual`(사용자 조치) |
| `supersedes` | 같은 로그에서 함께 매칭될 때 지워지는 더 일반적인 ID (예: 구체적 SNAPHU 항목이 `KB-ENV-002` 를 대체) |
| `pattern_verified`, `pattern_source` | 패턴 문자열을 상류 소스·문서에서 확인했는지와 그 출처(규칙 11.3). 확인하지 못한 패턴은 `false` 로 두고 open-questions 에 행을 남깁니다 |

## 새 항목을 넣을 때

1. 실패 로그에서 **상류 소스에 실제로 있는** 문자열을 고르고 출처를 적습니다(`pattern_source`). 문구를 추측해
   패턴을 만들지 않습니다 — 확인되지 않으면 `pattern_verified: false` + open-questions 행.
2. `tests/fixtures/logs/<engine>/` 에 마스킹된 발췌(경로·토큰·호스트명 제거)를 넣고 `manifest.yaml` 에 기대 ID 를
   적습니다. 픽스처는 수 KB 이하.
3. 조치 문구는 "무엇을 바꾸면 되는지" 를 설정 키(`unwrap.tiles`, `engine.isce2.esd_coherence_threshold` …)나
   명령으로 씁니다. 한/영 둘 다.
4. `scripts/render_kb_docs.py --write-i18n` 실행 후 `pytest tests/unit/diagnose` — 패턴 컴파일, ko/en 키 존재,
   픽스처 매칭을 검사합니다.
5. 설계상 결정(예: 어떤 문구를 어느 엔진으로 볼지)은 ADR-0035 대역(0035–0039)에 남깁니다.

## English summary

The diagnosis knowledge base is a set of YAML files under `src/wintersar/diagnose/kb/` (one per engine) whose
entries (`KBEntry`: id, engine, stage, verified regex `pattern`, extracted params, ko/en `cause` and `fix`,
refs, severity, `retry_hint` of `retry_later`/`tile`/`manual`, `supersedes`, `pattern_verified` +
`pattern_source`) are matched against engine logs by `wintersar diagnose` and auto-attached to a failed `run`.
IDs are `KB-<ENGINE>-<NNN>`; unmatched logs yield `KB-UNKNOWN` with a masked excerpt. `docs/kb/index.md`,
`docs/kb/KB-*.md` and the `diagnose.<ID>.*` i18n strings are generated by `scripts/render_kb_docs.py`
(`--write-i18n`, `--check`) and must not be edited by hand; this README is the GitHub-facing overview because
MkDocs ignores a `README.md` next to an `index.md`. To add an entry: take a string that really exists in the
upstream source, record its provenance, add a masked log fixture with the expected ID in
`tests/fixtures/logs/manifest.yaml`, write cause -> fix in both languages, regenerate and run the diagnose tests.
